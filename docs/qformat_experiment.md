# Q 格式统一化对比实验（qformat_experiment）

> 回答老师疑问：**当前逐层 Q 格式（激活 frac=12/10/7/5/4/5、权重
> frac=15/15/14/14/15/14/15）是否太复杂，能否统一？**
> 结论先说：**不能统一，建议保持逐层定稿。** 最温和的统一方案也使 p99.9
> 超预算线 5%~70%，完全统一则超线 14~34 倍。数据如下。
>
> 日期：2026-08-12；实验脚本 `scripts/qformat_experiment.py`；
> 结论复现：`cd RL_project && python3 scripts/qformat_experiment.py`。

---

## 1. 实验设置

- 只改 golden model 侧 `cfg.Q_FORMAT`（实验脚本在内存中 monkey-patch，
  跑完恢复，**不落盘改 config、不动 RTL、不动 tests 既有断言**）。
- 采样与统计完全复用 `scripts/fixed_point_stats.py`：同一 seed=20260812、
  同 2 万组包络样本、同一条 bit-true 定点链 / float64 浮点参考链。
  基线复跑精确复现 p99.9=1.437 / max=3.158（与 fixed_point_spec §6 一致），
  说明实验管线与验收脚本同源可比。
- 所有变体共享不变约束：权重 int16、激活 int18、输入 Q6.10、ELU LUT 256 档、
  40bit 累加器；**CUT_POS = acc_frac − act_frac 随各层 frac 联动重算**
  （`build_fixed_cache` 内自动），bias 按新 acc_frac 重新量化。
- 验收线（同 fixed_point_stats）：p99.9 ≤ 1.5 m/s、max ≤ 5 m/s、
  单层正支饱和率 ≤ 0.1%。

## 3. 关键观察

1. **统一激活（f=4 或 f=5）是灾难性的**，且死因不是溢出而是再量化噪声：
   所有变体正支饱和 0 次。f=4 时激活 half-LSB = 2^-5 ≈ 0.031（实数），
   layer_01/02 从 frac=12/10（half-LSB 2^-13/2^-11）直接掉到 4，
   早期层噪声被后续 5 层放大，p99.9 冲到 49.6 m/s（预算的 33 倍）。
2. **uni_f5 的 layer_05 量程风险属实但未触发**：f=5 时量程 ±4096，
   layer_05 浮点峰值 4051.7（spec §2），余量仅 1.1%；本 2 万样本内
   正支饱和 0 次，但分布外（OOD）样本随时可能钳位——属隐患而非本文
   FAIL 的主因（FAIL 主因仍是精度）。
3. **误差归因近似可加**：仅激活两档降档 +0.59、仅权重统一 +0.13、
   两者叠加（tier_10_4）+1.11。激活降档是主要矛盾，且 **前两层的
   frac=12/10 是精度命脉**（这两层 activation 值小、frac 高，正是在
   用满 int18 的动态范围换精度）。
4. **即使最小幅度的统一（仅权重全 14）也超线**：p99.9 = 1.571 >
   1.5（超 5%）。注意它 mean/max 反而略优（0.316/3.129），恶化集中在
   尾部 0.1% 样本——权重 15→14 的噪声主要在尾部分位显现。
5. **物理根源**：p99.9 预算 1.5 m/s 几乎贴着输入 Q6.10 的硬底
   （隔离实验 ≈1.33 m/s，spec §6），留给权重+激活量化噪声的余量只有
   ~0.2 m/s（尾部分位上各噪声源同向叠加）。当前逐层格式已经把 int16
   权重 / int18 激活的动态范围吃到接近极限，任何 frac 收紧都会穿透预算。

## 4. "统一能省什么"的硬件账

统一 frac 在硬件上几乎不省资源：

- CUT_POS、ELU 的 fbits/ibits/lut_base 本来就是**逐层常数**，RTL 用
  `case (layer_idx)` 查表（fc_engine.v），统一后这张表依然存在，只是
  数字相同——移位器、LUT、数据通路位宽（int16/int18/40bit）完全不变。
- 统一后省掉的只是 config 里 13 个参数数字和文档里一张表；综合后的
  LUT/FF/DSP/BRAM 不会有可见差别。

收益≈0、代价 = p99.9 超线 5%~3300%，账不成立。

## 5. 给老师的建议

**保持逐层 Q 格式定稿（base），不做统一化。**

- 逐层格式的"复杂度"已被工程手段消化：唯一事实来源是
  `config/model_config.py` 的 `Q_FORMAT` 两个 dict，golden model、
  ROM 生成、RTL 参数表全部从它派生；改格式只需改一处，不存在多处
  写死数字的维护负担。
- 若将来老师仍希望简化，唯一"可谈"的候选是 **仅统一权重 frac=14**
  （uni_w14）：p99.9 = 1.571，超线约 5%（在 seed 间波动范围内，
  mean/max 反而略优）。但按定死的验收线它仍是 FAIL——要采纳它需要
  把部署误差预算从 1.5 放宽到 ~1.6 m/s 或接受尾部风险，**不推荐**。
- 激活 frac 任何形式的降档/统一（两档 10/4 也不行，p99.9 = 2.55）
  都明确不可接受。
